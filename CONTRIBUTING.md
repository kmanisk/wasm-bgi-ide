# Contributing

Contributions are welcome. Keep pull requests focused and preserve the existing browser IDE behavior unless the change intentionally modifies it.

## Workflow

1. Branch from `main`.
2. Follow the setup instructions in `README.md` and confirm the project runs before changing it.
3. Keep code, UI, and documentation changes scoped to one purpose per pull request.
4. Run the relevant formatter, linter, build, and tests available in the repository.
5. Explain the user-visible effect and the validation performed in the pull request.

For UI changes, include screenshots when useful. For compiler/runtime changes, include a small reproducible input or test case. Do not commit credentials, local caches, generated build output, or editor-specific files.
